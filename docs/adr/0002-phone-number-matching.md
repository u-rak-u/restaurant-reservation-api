# ADR-0002: 電話番号照合に鍵付きハッシュを使用する

## 状態

採用済み（2026-08-20）

## 背景

MVPでは独立した顧客エンティティを作らず、管理責任者が確定した無断キャンセルと同じ電話番号による新しい予約へ、スタッフ限定の要確認警告を表示する。

電話番号にはハイフン、空白、国内形式、国際形式などの表記差がある。また、電話番号は候補範囲を推測しやすく、通常のハッシュだけでは候補番号を総当たりして照合される危険がある。一方、警告の判定に電話番号を復元する必要はない。

## 判断対象

電話番号をどの形式へ正規化し、無断キャンセル履歴との完全一致に使う値をどのように保護し、秘密鍵をどのように更新可能にするかを決定する。

## 検討した選択肢

### 1. 正規化済み電話番号を直接検索する

- 実装と障害調査が単純である。
- 照合用インデックスと検索処理が電話番号そのものを扱い、目的外利用または漏えい時の影響が大きい。

### 2. 秘密鍵を使わないSHA-256

- 元の電話番号を直接保存せず、完全一致検索ができる。
- 同じ電話番号から常に同じ値が作られ、攻撃者が候補番号を事前計算して照合できるため、電話番号のような候補範囲の狭い値には不十分である。

### 3. 決定的暗号化

- 暗号文の完全一致検索と、必要な場合の復号ができる。
- 今回の照合値は復元する必要がなく、暗号モード、nonce、復号権限を含む不要な複雑さが増える。

### 4. 専用秘密鍵によるHMAC-SHA-256

- 秘密鍵を持つアプリケーションだけが同じ照合値を計算でき、復号機能を持たずに完全一致検索ができる。
- 秘密鍵の保管、バージョン管理、更新、漏えい時の再生成手順が必要になる。

## 採用した案

電話番号をE.164形式へ正規化し、次の要素から専用秘密鍵によるHMAC-SHA-256照合値を作成する。

```text
HMAC-SHA-256(
  専用秘密鍵,
  "no-show-phone:v1|店舗ID|E.164電話番号"
)
```

- `+` がない入力は日本の番号、`+` がある入力は国際番号として解析する。
- 固定電話を含む電話連絡可能な番号を受け付け、英字と内線番号はMVPでは受け付けない。
- 正規化前の入力値は別に永続化せず、予約にはE.164形式の番号を保持する。
- 無断キャンセルが確定した場合だけ照合値を保存し、店舗を越えて照合しない。
- 警告状態は予約へ保存せず、スタッフ向け読み取り時に保持中の照合値から派生させる。公開予約作成処理では照合しない。
- 照合値へ鍵バージョンと正規化方式バージョンを付ける。
- 鍵更新中は新旧の読み取り可能な鍵で候補値を計算し、保持中の値を新しい鍵へ段階的に再生成する。
- 秘密鍵はDB、ソースコード、ログへ保存せず、他用途の秘密情報と共用しない。
- 開発環境ではGit管理外の環境設定、本番ではシークレット管理機能から鍵を取得する。
- 照合値は無断キャンセル確定から1年で全鍵バージョンを削除する。

## 採用理由

表記差を正規化しながら、無断キャンセル検索用インデックスへ平文電話番号を置かず、復号機能も持たせずに完全一致検索を行えるためである。これは照合用途の分離と偶発的な露出の低減を目的とし、予約連絡先を含むDB全体の漏えい対策として扱うものではない。

店舗IDを入力へ含めることで、将来複数店舗になっても店舗を越えた同一電話番号の関連付けを標準動作にしない。鍵と正規化方式へバージョンを付けることで、保持中の照合機能を止めずに段階的な移行ができる。

## デメリット

- HMAC照合値も既知の電話番号と照合できる個人情報であり、匿名情報として無期限に残せない。
- 保持中の予約連絡先へアクセスできる主体には電話番号自体が見えるため、HMACだけではDB全体の漏えいから電話番号を保護できない。
- 秘密鍵を失うと既存値を照合できず、漏えいした場合は鍵更新と保持中の値の再生成が必要になる。
- 電話番号の誤入力、家族共用、再割り当てによる別人の一致を防げない。
- 電話番号解析ライブラリのメタデータ更新と、入力・正規化の境界値テストが必要になる。
- 鍵更新中は複数鍵による候補値計算と、同じ予約に対する複数バージョンの一時保持が必要になる。

## 将来見直す条件

- 複数店舗間で無断キャンセル情報を共有する正当な利用目的、顧客説明、アクセス権限、保持方針が確立した。
- 顧客アカウントまたは検証済みの電話番号を導入し、電話番号一致以外の本人識別方法を利用できるようになった。
- HMAC-SHA-256または使用する鍵管理基盤に対するセキュリティ要件が変更された。
- 国際番号、内線番号、番号種別に関する受付要件が変わった。

見直す場合も、電話番号の一致だけで同一人物と断定し、自動的に予約を拒否する方式へは変更しない。
