# 店舗テーブルレイアウト

## 1. 文書の目的

この文書は、MVPで使用する単一店舗の席数、テーブル属性、配置、連結可能関係を定める。
業務要件は `docs/requirements.md` を正とし、この文書は自動割り当てを検証するための具体的な店舗設定を示す。

## 2. 店舗規模

**確定**

- 総席数は40席とする。
- 1予約の人数は1名以上12名以下とする。
- 13名以上はオンラインで受け付けず、店舗への電話相談を案内する。
- 1つの連結席で収容する最大人数は12名とする。
- 1予約で使用するテーブルは最大6台とする。

## 3. 配置

```text
                         窓側

  可動2名席エリアB                  独立4名席

  ───────────────── 通路 ─────────────────

  固定ボックス席
  [B01/4]       [B02/4]       [B03/4]

                         入口
```

## 5. 連結可能関係

**確定**

直接連結できる組み合わせだけを登録し、それ以外の組み合わせは隣接関係から生成する。

| テーブルA | テーブルB |
|---|---|
| T01 | T02 |
| T02 | T03 |
| T03 | T04 |
| T04 | T05 |
| T05 | T06 |
| T07 | T08 |
| T08 | T09 |
| T09 | T10 |

- 有効な連結候補は、登録済みの隣接関係によってすべてのテーブルが連続している組み合わせとする。
- 例えば `T01 + T02 + T03` は有効、`T01 + T03` は無効とする。
- エリアAとエリアBの間、通路をまたぐ位置、独立4名席、固定ボックス席は連結できない。
- 2名席は連結部分に席を設けない前提とし、連結後の定員は各テーブルの定員の合計とする。
- 連結可能関係は物理的に安全な配置として店舗が事前確認したものだけを登録する。

## 6. 生成できる最大連結席

| エリア | 最大連結台数 | 最大収容人数 |
|---|---:|---:|
| A | 6台 | 12名 |
| B | 4台 | 8名 |
| 独立席 | 1台 | 4名 |
| ボックス席 | 1台 | 4名 |

## 8. 実用性評価

- 直線状の隣接関係であるため、最大6台まで連結しても候補生成を制御しやすい。
- 独立4名席、固定ボックス席、可動2名席があり、単独席と連結席の優先順位を検証できる。
- エリアAを小人数予約で分断すると9名以上を収容できなくなるため、単純な余剰席数だけでは実用的な割り当てにならない可能性がある。
- 静的な隣接関係は、営業中にテーブル位置を自由に変更しないことを前提とする。
- 物理的な通路幅、配膳経路、安全性はAPIだけでは保証できないため、登録する配置を店舗側で確認する必要がある。
- 13名以上を複数予約へ分ける場合、MVPでは一括変更、一括キャンセル、近接席の保証ができない。
