# 予約なし利用追加による要件影響の再確認

## 1. 目的

予約なし利用をMVPへ追加したことで、完了済みとしていた要件のうち再検討が必要になった範囲を明確にする。
予約なし利用の存在そのものは採用済みだが、関連する業務ルールが未確定のままドメインモデルやDB設計へ進まないようにする。

## 2. 現在の状態

**再検討中**

次の基本方針は確定済みとする。

- 予約なし利用を予約とは別の業務データとして管理する。
- 顧客の氏名、電話番号、予約番号、確認コード、QRコードを持たせない。
- スタッフが来店時に登録し、将来の予約なし利用を事前登録しない。
- 予約と同じ物理テーブル、配置場所、連結可能関係を使用する。
- 利用中の席を予約の自動再配置によって動かさない。
- 待ち行列、注文、会計、顧客プロフィールをMVPに含めない。

一方、次の項目はウォークイン追加前には存在しなかった判断である。再検討対象として管理し、合意した項目から確定状態を明示する。

## 3. 再検討する項目

### W-01 利用開始条件と営業時間

**確定**

- 各営業時間帯に開店、最終入店、ラストオーダー、閉店を設定する。
- 予約なし利用は、受付日時が最終入店日時以前で、予定終了日時が同じ連続営業時間帯の閉店日時以前の場合だけ受け付けられる。
- 最終入店日時ちょうどの受付と、閉店日時ちょうどの利用終了を許可する。5名以上は最終入店以前に受付を完了していれば、準備後の予定利用開始が最終入店を過ぎてもよい。
- 日付をまたぐ場合は、実日時を変更せず営業時間の開始日に属する営業日として扱う。
- 定休日と臨時休業では受け付けられず、特別営業時間では同時間帯に明示した最終入店とラストオーダーを使用する。
- 貸切中は対象範囲の席候補が競合するため受け付けられない。貸切自体には最終入店とラストオーダーによる受付制限を適用しない。
- ラストオーダーは案内と受付判定の前提となる設定だけを管理し、注文内容と実際の注文時刻はMVPで扱わない。

### W-02 予定利用時間

**確定**

- 初期値90分、最小60分、最大180分、10分単位とする。
- 予定利用時間は利用開始前にだけ選択し、開始後の延長と短縮をMVPに含めない。
- 90分未満では終了予定時刻を顧客へ案内し、案内したスタッフと日時を記録する。
- 早期退店は予定終了を変更せず、利用終了操作によって処理する。
- 予定終了10分前を終了間近、予定終了後を時間超過として表示する。
- 時間超過しても自動終了せず、実際の利用終了まで席を占有中として新しい利用へ割り当てない。
- 後続予約がある場合は強い警告を表示し、退席案内または席移動は現場で対応する。

### W-03 人数変更と13名以上

**確定**

- 現在人数は1名以上12名以下で変更でき、全員退店は利用終了として扱う。
- 減員しても席を解放せず、増員は現在の割り当て定員内に限り通常スタッフが人数だけを変更できる。
- 割り当て定員を超える追加参加者は、別の予約なし利用として空席を探索する。
- 13名以上はスタッフが各1名以上12名以下へ分割して入力し、全員分を収容できる場合だけ同じトランザクションで全件を作成する。
- 分割した各件を恒久的に関連付けず、変更と利用終了は個別に行い、近接席も保証しない。
- スタッフは離れた席になる可能性を案内し、自動配置を使う限り合計人数だけを理由とする責任者承認を要求しない。

### W-04 席配置と転換時間

**確定**

- 1名から4名は受付と同時に `active`、5名以上は受付と同時に `preparing` とし、準備中から席を確保する。
- 5名以上の予定利用開始日時は受付日時から店舗設定の大人数転換時間が経過した日時とし、予定終了日時はそこから予定利用時間を加えて求める。
- 準備が遅れても予定終了日時を自動延長せず、予定利用開始日時を過ぎた `preparing` を警告表示する。
- 5名以上は利用終了後も、実際の終了日時から大人数転換時間が経過するまで席を確保し、経過後に清掃完了操作なしで自動的に解放する。
- 早期終了時は終了後転換時間を実際の終了日時から計算し直すが、既存予約の席配置は組み直さない。
- `preparing`、`active`、利用終了後転換時間中の席は、新規受付による自動再配置の対象にしない。

### W-05 操作権限

**確定**

- 通常スタッフは、自動選択された席で準備開始、利用開始、利用終了を行える。
- `preparing` の受付中止は通常スタッフが行えるが、理由を必須とし、履歴を削除せず `aborted` にする。
- 当日運用責任者以上は、受付時に競合しない別候補を選択できる。
- 当日運用責任者以上は、安全上または顧客対応上の理由を記録し、競合を再検証して `active` な予約なし利用を別の席へ移動できる。
- 利用終了を通常操作で取り消さず、誤終了は例外案件として提起する。営業中に占有を継続する場合は、元の記録を戻さず新しい予約なし利用を作る。

### W-06 営業設定、貸切、臨時休業との関係

- `active` な予約なし利用と競合する貸切を必ず拒否するか。
- 利用中に臨時休業を登録した場合、予約なし利用を要対応として扱うか、即時の現場対応だけにするか。
- 営業時間または特別営業時間の変更時に、`active` な予約なし利用も既存予約と同様に検証対象へ含めるか。

### W-07 状態訂正と例外案件

- 誤って別の人数または席で利用開始した場合の訂正方法。
- 誤って利用終了した場合は元の記録を `active` へ戻さない方針を前提として、例外案件種別、営業中に作る新しい利用記録との関係、席占有の引継ぎ方法をどうするか。
- 予約の来店訂正と予約なし利用の訂正を同じ例外案件種別へまとめるか。

### W-08 保持期間と監査

- 個人情報を持たない予約なし利用本体、席配置、人数、利用日時をいつまで保持するか。
- 利用開始、変更、終了、訂正の監査履歴へ既存の3年保持を適用するか。
- 統計用データとして期限後も保持できる範囲をどうするか。

### W-09 スタッフ画面とMVP境界

- 予約なし利用の受付画面、準備中・利用中一覧、利用開始・終了操作に表示する情報と操作導線をどうするか。
- 準備遅延と終了後転換時間中をどの表示で区別するか。
- 終了間近と時間超過の警告をスタッフ画面へ表示する方針は確定済みとする。
- 予約一覧と予約なし利用一覧を同じタイムラインへ表示するか。
- 待ち行列をMVP後へ回したまま、満席時は登録を拒否するだけでよいか。

## 4. 再検討しない既決事項

次の要件は予約なし利用を追加しても意味が変わらないため、確定状態を維持する。

- 顧客アカウントをMVPで作らない方針
- 予約番号、予約確認コード、QRコードの用途と安全性
- 通常予約のオンライン取消と電話受付
- SMS、メール、電話対応管理をMVP後へ回す方針
- 通常予約の受付開始、受付締切、変更・キャンセル締切
- 通常予約と貸切予約を共通の予約集約で扱う方針
- 貸切の資格情報の受け渡しと再発行方法
- 無断キャンセル履歴を使った利用制限のMVP範囲

## 5. 決定順

1. W-06の営業時間、貸切、臨時休業との関係を決める。
2. W-07の例外案件と訂正方法を、他の例外案件分類と一緒に決める。
3. W-08とW-09の保持期間と画面範囲を確定する。
4. 要件定義を再び完了としてから、ドメインモデルとDB設計へ戻る。

## 6. 実用性評価

予約なし利用を席計算へ含めること自体は、実店舗の空席とシステム上の空席を一致させるために有効である。
ただし、上記を決めずに実装すると、終了超過で予約客の席がなくなる、通常スタッフが誤操作を復旧できない、貸切と利用中席が競合するなどの運用上の欠陥が残る。

現在はDB設計と本格実装の前であるため、この段階で要件へ戻るコストは小さい。
先に再検討を完了する方が、後から予約モデル、席配置制約、API権限を作り直すより実用的である。
